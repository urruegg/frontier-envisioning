Sources of the Frontier Company Blueprint HTML: `skeleton.html` (page shell with the `/*__CSS__*/` and `/*__JS__*/` slots and the JSON data island), `template.css` and `template.js` (17 available core routes, including Ontology after Target architecture; optional FinOps adds an eighteenth route). `python tools/dev.py template` assembles them into `plugin/skills/frontier-blueprint/templates/frontier-blueprint-template.html`, which `build_blueprint.py` fills with a blueprint's data. Rules: `.github/instructions/renderer.instructions.md`.

The optional `parts` labels/descriptions override navigation copy without changing route IDs. PRD requirements use the embedded shared Python model's IDs; the Markdown download does not renumber them. Plan derives stages from the existing Agent Factory checks and supports journey/MVP filtering. Its CSV is a handover format requiring destination field mapping, not a native Azure Boards or GitHub Projects import. WIP limits are advisory, not approval.

Risk ratings, status and notes use `risk:<id>` feedback validations; MVP scope uses `prd:scope`. They share the existing localStorage namespace and Discovery JSON/text exports. Optional PRD/risk fields hide unavailable pages; Plan falls back to default phases/checks without a board configuration. Keep the current modal, keyboard, contrast and locally scrollable layout safeguards when extending these views.

Ontology requires actual entity IDs; sparse/older data hides the route. Its native disclosures cover mappings, medallion/domains/models, governance, sources, agents, rules, metrics and readiness. Selection and journey filters retain keyboard focus and clear hidden selections. `onto:<id>` feedback keeps D1 IDs (model, entities, relationships, data agents, operations agents and products); unknown IDs are reported and retained for review, not silently assigned. Opaque `internal_notes` and cached exports are never used. Turtle mirrors Python `to_turtle`, tested against the actual built file and a UTF-8/escaping case. Semantic Markdown exports the supplied design projection, preserving source restrictions. Native Fabric import/binding remains manual; Fabric ontology/agent Preview is separate from the GA wrapper.

Any imported/legacy FinOps block or tagged derived value shows the exact Preview notice. Only an explicit viewer click enables provisional figures for that document instance; navigation never acknowledges and reload/new document resets it. Script/caller metadata is separate, not human approval or encryption/access control. No consent is saved in localStorage. Preview-derived NPV/ROI/cost/payback and ranking are withheld consistently in use cases, portfolio, PRD and its download; ordinary non-FinOps value, evidence and workshop notes remain usable. Redacted totals, units, scenarios or ranks are unavailable, never inferred from opaque notes or replaced by zero. Modelled costs never pass budget readiness automatically. Comparisons are provisional, not purchase recommendations; the warning stays visible after acknowledgement.

Portfolio provenance includes its actual contributing cases, even if the FinOps block and aggregate marker are absent. It gates totals and all ranking/sensitivity presentations together without recomputing a public-only subset as a full portfolio; independently public cases remain available in the UI and PRD export. Assumptions use their own marker or FinOps-register source identity, including copies linked from a value case or feedback-loop outcome. The same projection withholds model figures/text and numeric verdict inputs/exports before acknowledgement, retains source references and authored notes, and leaves ordinary GA assumptions usable. Stored verdicts are never overwritten by the presentation gate; acknowledgement restores provisional numeric presentation and reload resets it.

The shared case-value resolver supports both flat `business_value` and `business_value.results`. Every value presentation (including PRD Markdown), case/portfolio provenance and NPV sensitivity uses that selection; markers and linked assumptions from either layer remain ancestry regardless of GA/cached-ack claims. Nested financial fields are authoritative, so missing nested amounts never recover stale outer financial fields. Independent outer benefits/metadata and public nested results remain usable.

Run `python tools/dev.py template demo dom` and `python tools/dev.py site e2e`. Core and explicit technical-ack Preview fixtures have separate real hosting CSP hashes; viewer acknowledgement is deliberately exercised by tests, not inferred from that fixture metadata. Feature regressions and actual Markdown/CSV/feedback downloads live in the `handover-17` tests; ontology byte-stream downloads, feedback, transient gates and light/dark/reflow coverage live in the `ontology-preview` tests. Browser tests attach light/dark screenshots at 1440px and 320px. Package/full release gates remain a separate handover step.
