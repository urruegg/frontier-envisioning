## 3. FinOps awareness and optionality

### Notice

Before an operation or showing Preview-derived cost figures:

> Frontier FinOps is Preview. Its grounding and cost model are not GA and need
> refinement. Results are provisional planning estimates, not validated pricing,
> budget approval or purchase/commitment advice. Verify rates and assumptions
> independently before decisions.

Loading the skill to explain this warning is permitted; calculation, model
seeding/application, cost-based recommendations and figure display are not
permitted until explicit acknowledgement.

### Scope and invalidation

Each top-level cost invocation requires `--acknowledge-finops-preview`; there
is no saved/global opt-in. The skill first obtains real confirmation for the
current scenario and versions. A wrapper may forward that acknowledgement only
within the same requested operation chain. A subsequent run, changed scope,
model, rates or grounding requires renewed acknowledgement.

Metadata records the technical caller acknowledgement and versions/fingerprints;
it does not assert independent human approval. Existing files, loaded JSON,
installed skills, previous notes and a request to discuss costs are not evidence
that the current warning was understood. Pure deterministic arithmetic helpers
remain independently testable; operational model entry points enforce the gate.

A direct requested cost action without acknowledgement returns an explicit
error before cost writes. A user decline skips the optional subflow and lets
the core engagement proceed, with a truthful skipped-step message. Missing
FinOps is not an import-time dependency of the core.

### Propagation

Preview status, non-GA grounding/model limitations, model/rate/source versions,
assumptions and scenario provenance follow JSON, HTML, Markdown, replies,
downloads, purchase comparisons and guardrail proposals.

GA value/design work without FinOps remains supported. Explicit user-supplied
cost assumptions retain ordinary evidence/confidence handling. Preview-derived
ROI, unit costs or cost-linked PRD figures must not silently appear as GA or
be substituted into the core without acknowledgement.

Legacy/imported FinOps figures are treated as Preview, not grandfathered into
GA. Browser viewing needs explicit transient acknowledgement for that blueprint;
the warning remains visible afterwards. It does not authorise script execution
or persist as a global/localStorage consent setting.

Existing installed FinOps receives the new gated procedure through the normal
eight-skill update. Installation may report Preview availability, but does not
acknowledge its use. Preserve real budget/owner accountability: optional FinOps
does not mean pretending that missing cost evidence meets readiness.

## 4. Build profiles and distribution

The default curated demo exercises the requested GA process feature and core
value/identity work **without FinOps invocation or model figures**. An explicit
developer Preview demo uses separate output and the acknowledgement flag; its
results are Preview test evidence, not human purchase approval.

Optional view tests assert route identity/availability, not totals alone. A
core demo with Ontology but without FinOps may have seventeen views, which is
not the same seventeen-view set as the old demo. The explicit Preview path can
exercise eighteen available views and still needs viewer acknowledgement.

Ship one eight-skill plugin ZIP and the default core complete bundle. Extend
the complete bundle's explicit allowlist only with the four named ontology
design/import documents under `demo/ontology/`; do not restore analysis/intake
wildcards. With those outputs, the expected complete inventory is fifteen
entries. Explicit Preview demo/cost JSON are kept out of that default bundle.
Both maturity tiers and limitations remain clear in packaged instructions.

Use the standard bump/regeneration tools. New 1.9.1 raster support is finite and
requires actual generated input verification; preserve original profiles/assets
and A6 corrections. Stop on unexpected inputs rather than enabling arbitrary
future versions or changing golden hashes.
